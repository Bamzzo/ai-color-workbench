# ADR-007：参数集扩展到 v2（16 参数）

## 状态

已采用（2026-10-20）。

## 背景

v1 只有 7 个参数（曝光、对比度、色温、色调、高光、阴影、饱和度），能表达“亮一点/
暖一点”，但表达不了摄影软件里最常用的几类意图：

- 抬高黑位做出褪色、胶片感（需要 blacks，而不是把 shadows 拉满）；
- 保护肤色地提鲜艳度（需要 vibrance，而不是 saturation）；
- 阴影偏青、高光偏暖的电影感（需要分离色调，而不是全局色温）；
- 整体色相偏移（需要 hue）。

需求来自对 Lightroom Basic/Color Grading 面板、DaVinci 色轮与 Darktable 的对照：
其中可移植到“逐像素 RGB 映射”的部分，只有全局色调、存在感（presence）中的
vibrance 与分离色调；Clarity/Texture/Dehaze 依赖局部邻域或场景估计，Vignette/Grain
依赖空间坐标，均不适合只用 3D LUT 实现，因此没有加入。

## 决策

新增 9 个字段，参数总数 16，`schema_version` 升为 `2.0`，算法版本升为
`sdr-srgb-v2`：

| 字段 | 范围 | 语义 |
| --- | --- | --- |
| `whites` | ±100 | 只作用于亮度 > 0.5 的一半，平方权重，提高/降低白点 |
| `blacks` | ±100 | 只作用于亮度 < 0.5 的一半，平方权重，抬起/压死黑位 |
| `vibrance` | ±100 | 以 `1 - chroma` 加权的饱和度，低饱和像素变化更大 |
| `hue` | ±180° | 保持亮度权重的 3×3 色相旋转矩阵 |
| `split_shadow_hue` / `_amount` | 0–360 / 0–100 | 阴影着色色相与强度 |
| `split_highlight_hue` / `_amount` | 0–360 / 0–100 | 高光着色色相与强度 |
| `split_balance` | ±100 | 移动阴影/高光着色的分界（±0.25 亮度） |

处理顺序（`transform_rgb`，全部在编码 sRGB 域）：

```
解码 → 曝光 → 色温/色调增益 → 裁剪重编码 → 对比度
→ 阴影/高光 → 白色/黑色 → 色相旋转 → 饱和度 → 自然饱和
→ 分离色调 → 裁剪输出
```

设计约束：

1. 全零时必须是**精确恒等**：每个新步骤都用 `if value:` 短路，不引入浮点噪声。
2. 不引入空间、邻域或逐图统计量，保证可烘焙为 3D LUT（ADR-003）。
3. 白色/黑色用半区平方窗，避免与高光/阴影重复；中灰处权重严格为 0。
4. 色相旋转用亮度权重矩阵（与 CSS `hue-rotate` 同族），灰色像素保持不变。
5. 分离色调的着色权重用当前亮度平方，强度上限 0.30，避免把整幅图染成单色。

## 兼容性

- `validate_params_document` 按文档里的 `schema_version` 选择 v1 或 v2 校验器；
  v1 文档通过后把 9 个新字段补 0 再归一化。旧预设、旧 AI 返回值和旧导出 JSON
  因此保持原样，不会突然变色。
- v2 文档必须写全 16 个键，AI 少写字段仍会被拒绝并触发一次修复请求。
- `ALGORITHM_VERSION` 进入 LUT 缓存键，升级后旧缓存自动失效，不会读到错误 LUT。

## 后果

- 侧栏放不下 16 个滑块，参数面板改为两个页签（基础 / 分离色调），并给整栏加
  垂直滚动；滑条数值标签对色相类参数显示角度和色块。
- system prompt、离线模板、预设文件与测试夹具同步升级。
- 33³ LUT 的近似误差（`tools/measure_lut.py`，145,937 点）在新增预设下最大
  2.32/255、p99 ≤ 1.18；导出时沿用既有的“超过 2/255 自动升 65³”策略。
