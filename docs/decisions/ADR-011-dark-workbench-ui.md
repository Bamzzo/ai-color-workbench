# ADR-011: 深灰调色工作台主题与状态分层

**状态：**已采纳（2026-11-11）
**范围：**`app/theme.py`、`app/widgets.py`、`app/ui.py`、`app/batch_ui.py` 的视觉与布局层
**不涉及：**颜色数学、LUT 生成、渲染协议、图像/视频 I/O、AI 调用、任务调度、导出队列语义

## 背景

改造前应用使用 ttk `vista` 原生主题：浅色工具栏与侧栏围绕深色预览画布，系统控件
无法着色；长文件名会撑开工具栏；预览/AI/导出/批次状态共用 `busy_var` 与
`message_var` 两行文本，互相覆盖；批次列表用浅色主题色定义状态标签，在深色行上
对比度不足。这些问题影响专业感、信息层级与可读性，但不属于核心处理链路。

## 决策

### 1. 用 `clam` 作为 ttk 基主题，集中管理设计令牌

`vista` 由系统绘制，忽略 `background`/`fieldbackground` 等设置，无法形成统一深色
工作区。改用 Tk 自绘的 `clam`，并在新模块 `app/theme.py` 中定义唯一调色板：

| 令牌 | 值 | 用途 |
| --- | --- | --- |
| `canvas` / `canvas_edge` | `#15171a` / `#0f1113` | 预览底与画布内框（非纯黑） |
| `window` | `#1f2226` | 窗口背景 |
| `surface` | `#272b30` | 工具栏、侧栏、状态栏 |
| `surface_alt` / `surface_high` | `#2e3338` / `#353b41` | 输入框、列表行、悬停 |
| `input` | `#1b1e22` | 可编辑字段（凹陷） |
| `border` / `border_strong` | `#3a4046` / `#4a5158` | 分隔与描边 |
| `text` / `text_muted` / `text_disabled` | `#e4e6e8` / `#9aa1a8` / `#6b7177` | 文字层级 |
| `accent` / `accent_dim` | `#4c8dff` / `#2b4b78` | 焦点、选中、进行中 |
| `ok` / `warn` / `error` | `#5bb98c` / `#d8a657` / `#e0716f` | 语义状态 |

对比度用 `theme.contrast_ratio()` 计算并在 `runtime/ui_theme_check.py` 中断言：
正文 ≥ 7:1、次要文字与状态色 ≥ 4.5:1。（实测：正文 11.38、次要 5.45、成功 5.94、
警告 6.45、错误 4.59。）

所有尺寸以 96 dpi 逻辑像素表达，由 `Theme.px()` 乘以显示缩放；不写死分辨率坐标。

参数读数用 `Value.TLabel`（已偏离默认）与 `ValueZero.TLabel`（仍为默认，弱化）区分，
只改颜色不改字号，因此不会影响数值可读性或行高。

### 2. 状态分层：并行的四个字段 + 一行“最后结果”

| 字段 | 内容 | 样式来源 |
| --- | --- | --- |
| `preview_chip` | 无素材 / 渲染 rev N / rev N 已更新 / 待更新 / 渲染失败 | 角色色 |
| `ai_chip` | 请求中 / 提案待确认 / 离线模式 / 就绪 | 角色色 |
| `export_chip` | 导出中（含排队数）/ 上次成功、失败、取消 | 角色色 |
| `batch_chip` | 运行中 完成/总数·剩余·失败 / 上次批次结果 | 角色色 |
| `busy_var` | 当前活动串（保留原格式，测试依赖） | 运行色 |
| `message_var` | 最后一条结果/错误（导出通知仍受 6 s 保护） | 角色色 |

状态永远由“前缀文字 + 状态词 + 颜色”共同表达，不单靠颜色。`_refresh_busy()` 仍是
唯一的总活动行，保持既有测试与互锁语义不变。

### 3. 预览是视觉中心，错误贴在画面上

- 画布内边距、直方图独立条带、对比行分层保留。
- 左上角状态覆盖层增加 `gray50` 点阵底板，亮画面/暗画面上都可读。
- 预览失败时在画布底部居中显示“预览失败 · <原因>”，同时预览字段转为错误色；
  不再只写窗口底部的状态行。
- 空态改为标题 + 说明两层文字。

### 4. 长名称可截断，完整值必须可达

- 工具栏新增素材字段，名称中段省略到 34 字符，`Tooltip` 显示完整路径；窗口标题
  保留完整名称。
- 批次列表：素材名在独立列，单元格裁切时使用横向滚动条；悬停任意行显示完整源路径、
  状态、错误与输出路径；选中行在页脚显示 `源：… → 输出：…`。
- 输出路径长时，“说明/输出”列显示文件名，完整路径进入悬停提示与选中详情。

### 5. 批次窗口只改表现层

保留：串行队列、取消当前/后续/全部、失败后继续、重试、统一参数/逐项覆盖、来源
变更检测、导出互锁。改动限于：

- 起始策略说明文字（并明确“参考素材协调”未启用，禁用 + tooltip，不伪造入口）。
- 状态列文字 + 行标签：失败/成功/进行中/取消/跳过使用主题语义色，且始终有文字。
- 页脚增加“当前项、完成、剩余、失败”计数与选中项完整路径。
- 最小尺寸改为 860×520（× 缩放），标题栏与主窗口一致。

### 6. 深色标题栏

Windows 下用 `DwmSetWindowAttribute`（20/19 + Win11 的 35/36/34）把标题栏染成
`#272b30`。Tk 在窗口映射时才创建真正的顶层 HWND，构造期设置会落在临时句柄上，
因此 `bind_dark_titlebar()` 在 `<Map>` 与 250 ms 后各重试一次。

## 后果

- 主题从系统原生外观变为应用自绘外观；这是有意的产品决策，代价是失去系统主题
  跟随。ttk 控件（含下拉列表）均已在 `theme.apply()` 中着色。
- 状态文字与布局断言进入 `runtime/ui_theme_check.py`：对比度、工具栏不重叠、
  侧栏可滚、直方图不被裁切、字段可见、最小尺寸、Tab 顺序、批次按钮不被裁切。
- `tk scaling` 模拟只能验证几何与字体度量，真实 125%/150% 显示器仍需人工看一眼；
  本机为 200%，已额外跑 200% 档。
- 未引入任何新依赖（仅 ctypes/DWM，Windows 可选路径）。
