# ADR-009：本地日志可记录素材路径（修订 ADR-005 §3）

## 状态

已采用（阶段 A）。修订 ADR-005 第 3 条，其余条款不变。

## 背景

ADR-005 第 3 条写“日志不记录源图路径、文件名”。这条规则的初衷是避免照片信息
外泄到 AI 服务，但在排障时它把最有用的线索也一并去掉了：导出失败究竟是哪个源、
写到哪个目标、是否发生源/目标重叠，靠 `request_id` 无法回答。

产品的实际规则（开发指导 §2.3）是：**本地日志允许记录源路径与目标路径**，前提是
日志只留在本机、不自动上传、不含密钥与用户提示正文。两者不冲突——要守的是
“不外传”，不是“不落盘”。

## 决策

1. 日志位置固定为 `runtime/logs/app.log`（UTF-8，追加写）。`runtime/` 已在
   `.gitignore` 内，属于本机运行数据。
2. 允许记录：源素材路径、导出目标路径、媒体类型、尺寸/时长、revision、
   任务耗时、ffmpeg/worker 的 stderr 摘要、稳定错误码。
3. 仍然禁止记录：API key、`Authorization` 头、用户对 AI 的完整描述正文、
   图像像素或像素采样数据。
4. 日志不自动上传，也不自动附加到反馈包。若未来要打包上传或随反馈发送，
   必须新增 ADR 并取得用户明确同意。
5. 清理方式：关闭应用后删除 `runtime/logs/app.log` 即可；删除不影响任何缓存或
   导出结果。当前未启用轮转，文件会随使用增长。

## 已知缺口

`app/main.py::_configure_logging` 使用普通 `FileHandler`，没有大小上限或轮转。
长批次运行会持续增长。是否改成按大小轮转属于独立决策（涉及保留多少历史），
本阶段只记录，不实现。

## 后果

- 排障可以从日志直接看到“哪个源导出到哪个目标、耗时多少、失败码是什么”。
- 日志的隐私边界从“不记录路径”收紧为“路径只在本地、不随任何请求发出”。
- ADR-005 的“不上传图像”结论不变；参考图/云端分析仍需新的 ADR 与用户同意。
